# 使用政策

> **草稿**。本文尚未經過律師審閱，在登錄庫對外開放之前會有變動。

登錄庫由所有以 Nabi 撰寫程式的人共同使用。本政策說明哪些內容可以發布，以及發生問題時如何處理。

## 名稱

- 名稱先到先得。名稱屬於最先發布它的帳戶，以及該帳戶新增的擁有者。
- 不要佔用你不會使用的名稱。沒有實際程式碼的套件（佔位用的套件、為日後保留的名稱）可能會被移除，其名稱可能轉給真正會使用的人。
- 部分名稱保留給 Nabi 專案：工具鏈的名稱（`nabi`、`nabic` 等），以及以 `nabi-`、`std-` 或 `core-` 開頭的名稱。標準函式庫的 `std`、`core` 與 `bare` 是 Nabi 專案自己的項目。
- 若將 `0` 與 `o`，`1`、`l` 與 `i`，`5` 與 `s`，`rn` 與 `m`，`vv` 與 `w`，大小寫，以及 `-` 與 `_` 視為相同後，新名稱與登錄庫中既有的名稱讀起來一樣，該名稱會被拒絕。
- 部分名稱也受到防仿冒保護：與這些名稱只差一個字母（四個字元以上）或讀起來相同的新名稱會被拒絕。受保護的是官方套件的名稱（由 nabi-lang 組織發布的套件，共用同一個命名空間）、工具鏈的名稱（`nabi`、`nabic` 等），以及熱門套件，也就是下載次數達 1,000 次以上的套件。與其他套件只差一個字母的名稱可以使用。
- 如果你的名稱被拒絕，但它確實是另一個不同的專案，請聯絡管理員核准。

## 刪除版本

- 版本發布後 72 小時內，只要沒有其他套件相依於該套件，擁有者可以在帳戶頁面或透過 API 刪除該版本。它的那一行會從索引中移除，壓縮檔也會從登錄庫中移除。它的版本號不會再被使用：修正必須以新版本發布。
- 超過 72 小時，或已有其他套件相依於它時，版本不會被刪除：請將它撤回。已撤回的版本會為固定了它的專案保留，新的相依解析則會略過它。
- 每次刪除都會被記錄，並以電子郵件通知該套件的擁有者。

## 不得發布的內容

- 惡意軟體，或做出使用者意料之外之事的程式碼：蒐集資料、挖礦、開設後門。
- 你無權發布的程式碼或其他素材。
- 垃圾內容、為了推廣某事物而製作的套件，或只是換個名稱複製另一個套件的套件。
- 他人的個人資料，以及違法或騷擾他人的內容。

## 使用 API

每個帳戶與每個位址每分鐘可進行的變更次數有限，一個帳戶每天最多佔用 10 個新名稱。不要試圖規避這些限制。

## 檢舉與下架

- 惡意套件、安全性問題或違反規則的情況，請檢舉至 security@nabi-lang.org（請見 [SECURITY.md](https://github.com/nabi-lang/nabi/security/policy)）。請註明套件、版本以及你看到的情況。
- 著作權及其他法律通知也寄到同一個位址。請說明你是誰、涉及哪些素材，以及你為何有權提出要求。
- 管理員在調查檢舉期間可以撤回某個版本，可以下架某個套件或版本（它會從網站上消失，API 會回應原因），也可以鎖定帳戶（無法登入，無法發布）。
- 每項處置都會被記錄。擁有者會收到原因說明，並可透過同一個位址回覆。經查證有誤的下架會被撤銷。
