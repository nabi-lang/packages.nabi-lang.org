# 使用政策

> **草稿**。本文尚未经过律师审阅，在注册表向公众开放之前会有改动。

注册表由所有用 Nabi 编写代码的人共同使用。本政策说明哪些内容可以发布，以及出现问题时如何处理。

## 名称

- 名称先到先得。名称属于首先发布它的账户，以及该账户添加的所有者。
- 不要占用你不使用的名称。没有实际代码的包（占位用的包、为以后保留的名称）可能会被移除，其名称可能交给会真正使用它的人。
- 部分名称为 Nabi 项目保留：工具链的名称（`nabi`、`nabic` 等），以及以 `nabi-`、`std-` 或 `core-` 开头的名称。标准库的 `std`、`core` 和 `bare` 是 Nabi 项目自己的条目。
- 如果把 `0` 和 `o`，`1`、`l` 和 `i`，`5` 和 `s`，`rn` 和 `m`，`vv` 和 `w`，大小写，以及 `-` 和 `_` 视为相同后，新名称与注册表中已有的名称读起来一样，该名称会被拒绝。
- 部分名称还受到防仿冒保护：与这些名称只差一个字母（四个字符及以上）或读起来相同的新名称会被拒绝。受保护的是官方包的名称（由 nabi-lang 组织发布的包，共用同一个命名空间）、工具链的名称（`nabi`、`nabic` 等），以及热门包，即下载量达到 1,000 次及以上的包。与其他包只差一个字母的名称可以使用。
- 如果你的名称被拒绝，但它确实是另一个不同的项目，请联系管理员批准。

## 删除版本

- 版本发布后 72 小时内，只要没有其他包依赖该包，所有者可以在账户页面或通过 API 删除该版本。它的那一行会从索引中移除，压缩包也会从注册表中移除。它的版本号不会再次使用：修复须作为新版本发布。
- 超过 72 小时，或已有其他包依赖它时，版本不会被删除：请撤回它。已撤回的版本会为固定了它的项目保留，新的依赖解析会跳过它。
- 每次删除都会被记录，并通过邮件通知该包的所有者。

## 不得发布的内容

- 恶意软件，或做出用户意料之外的事情的代码：收集数据、挖矿、开设后门。
- 你无权发布的代码或其他材料。
- 垃圾内容、为推广某物而制作的包，或只是换个名称复制另一个包的包。
- 他人的个人数据，以及违法或骚扰他人的内容。

## 使用 API

每个账户和每个地址每分钟可进行的更改次数有限，一个账户每天最多占用 10 个新名称。不要试图绕过这些限制。

## 举报与下架

- 恶意包、安全问题或违反规则的情况，请举报至 security@nabi-lang.org（见 [SECURITY.md](https://github.com/nabi-lang/nabi/security/policy)）。请写明包、版本以及你看到的情况。
- 版权及其他法律通知也发送到同一地址。请说明你是谁、涉及什么材料，以及你为何有权提出要求。
- 管理员在调查举报期间可以撤回某个版本，可以下架某个包或版本（它会从网站上消失，API 会返回原因），也可以锁定账户（无法登录，无法发布）。
- 每项处理都会被记录。所有者会被告知原因，并可通过同一地址回复。经查实错误的下架会被撤销。
